# Радар YouTube → инбокс CRM

**Дата:** 2026-09-16. **Статус:** реализовано (CRM-часть), Радар-часть следом.

## Задача
Заявки из «Радар Rossa» (парсер комментариев YouTube, отдельное приложение,
E:\dev\rossa-radar, прод на Vercel) должны, помимо телеграм-карточки в
@Rossa_Scout_bot, попадать в CRM как **чаты в инбоксе** на канале `youtube`,
в отдельной отфильтрованной ленте, чтобы сотрудники видели входящие и брали
в работу. Решение владельца: инбокс, не воронка лидов.

## Ключевое ограничение
YouTube не даёт ни контактов, ни личного канала — ответить можно только
публично под роликом. Значит переписка **без обратной отправки**: вместо поля
ответа — кнопка-ссылка на сам комментарий.

## Что уже было в CRM (не трогаем)
- `POST /api/public/v1/conversations/inbound` (scope `contacts.manage`) —
  создаёт переписку без контакта; неназначенные треды по коду видны всем.
- Канал `youtube` уже в белом списке (`conversation.py`), фильтр по каналу
  уже есть в списке переписок (`conversations.py`, репозиторий фильтрует),
  дедуп по `provider_message_id` встроен. **Бэкенд и БД не меняются.**

## Изменения (только фронт CRM)
1. **Фильтр каналов** на `/messages`: чипы `Все / YouTube / WhatsApp / …`,
   параметр `?ch=<channel>`, прокинут в `listConversations({channel})`.
   Фильтр сохраняется при выборе треда (`&ch=` в ссылке строки).
2. **Кнопка «Ответить на YouTube ↗»** вместо поля ответа для тредов канала
   `youtube`; ссылка берётся из `media` новейшего сообщения.
3. i18n-ключи `chanAll`, `ytReply`, `ytNoLink` в ru/en/pt-BR.

## Отображение заявки (что шлёт Радар в inbound)
| поле | значение |
|---|---|
| channel | `youtube` |
| from_address | id ютуб-канала автора (ключ треда) |
| from_name | имя автора |
| subject | название ролика |
| body_text | текст комментария |
| provider_message_id | id комментария → дедуп |
| lang + translations | язык + перевод от Радара |
| media | `[{kind:"file", url:"…&lc=…", name:"Ответить на YouTube"}]` |

Все комментарии одного автора → один тред; каждый коммент → сообщение.

## Радар-часть (репозиторий E:\dev\rossa-radar, вне заморозки CRM)
- `scripts/watch.mjs`: после телеграм-карточки — POST в inbound с
  `X-API-Key` и `Idempotency-Key: <commentId>`. Телеграм остаётся.
- Секреты GitHub Actions репозитория: `CRM_API_URL`, `CRM_API_KEY`.

## Дедуп
Двойной, оба по id комментария: `provider_message_id` (уровень сообщения) +
`Idempotency-Key` (HTTP). Почасовой пере-скан не создаёт дублей.
