# Рогнар-Rossa — разведка лидов для менеджера

Второй слушатель, брат-близнец `rognar/`. Отличий три, и все они существенные:

1. **другой аккаунт** — отдельный номер `+55 11 96842 2222`, свой файл сессии;
2. **другой получатель** — сигналы уходят не владельцу, а сотруднику отдела продаж;
3. **шире охват** — ловит не только покупку жилья, а все семь направлений агентства.

Всё остальное — как у первого: слушает чаты, где аккаунт уже состоит, и
**никому не пишет и никуда не вступает сам**. Решение о контакте принимает
человек.

```
публичные чаты
   ↓ (аккаунт-слушатель молча читает)
предфильтр по словам  ·  RU / EN / PT  ·  7 направлений
   ↓
модель: живой лид или трёп?
   ↓
бот-почтальон  →  сотруднику в ЛС
```

## Что ловим

| Направление | Примеры зацепок |
|---|---|
| недвижимость | купить квартиру, новостройка, вторичка, ипотека, риелтор, коммерческое помещение |
| аренда | снять дом, долгосрочная аренда, арендодатель, арендатор, `aluguel`, `long-term rental` |
| земля | земельный участок, участок под застройку, `terreno`, `land for sale` |
| инвестиции | инвестиции в недвижимость, доходность, окупаемость, ROI, `rental yield` |
| строительство | строительство дома, подрядчик, застройщик, дом под ключ, `construtora` |
| юридическое | сделка купли-продажи, юридическое сопровождение, проверка объекта, `escritura`, `due diligence` |
| ВНЖ | ВНЖ за инвестиции, вид на жительство, инвестиционная виза, `golden visa` |

Группы живут в `config.py` → `TRIGGERS`, каждая отдельным блоком — править можно
точечно, не задевая соседние. Проверка: `python rognar-rossa/test_filter.py`
(49 случаев, по всем направлениям сразу).

Слово-намерение без объекта не считается: «купить» рядом с гречкой — не лид.
Объявления (`продам`, `сдаю`, `vendo`, `for sale`) отсекаются до модели — но
только если в сообщении нет прямой просьбы о помощи: «сдаю квартиру,
посоветуйте агентство» — это клиент, а не реклама.

## Где он работает

**В бою — на VPS, в `/opt/rognar-rossa`.** Отдельный compose-проект (`name:
rognar-rossa`) со своей сетью и своим томом сессии: ни CRM, ни n8n, ни первого
Рогнара он не касается.

```bash
cd /opt/rognar-rossa
docker compose logs -f         # что происходит сейчас
docker compose restart         # перезапустить
docker compose up -d --build   # после обновления кода
```

Новые чаты подхватываются сами: сотрудник вступил с телефона — через несколько
минут слушатель уже слушает, перезапускать ничего не нужно.

> ⚠️ Один аккаунт — один запущенный слушатель. Второй клиент на том же файле
> сессии роняет первому поток обновлений; замок в `config.py` не даст запустить
> два разом.

## Настройки

Всё в файле `.env` рядом с compose (в git не попадает; локально — `.env.rossa`
в корне репозитория):

| Переменная | Что это |
|---|---|
| `ROGNAR_BOT_TOKEN` | бот-почтальон от @BotFather — **свой, не общий с первым Рогнаром** |
| `ROGNAR_OWNER_CHAT_ID` | `chat_id` сотрудника — берётся после его `/start` боту |
| `ROGNAR_API_ID` / `ROGNAR_API_HASH` | с https://my.telegram.org под номером слушателя |
| `ROGNAR_WATCH_JOINED` | `false` — слушать только `watchlist.txt` (по умолчанию слушает все группы аккаунта) |
| `AI_API_KEY` / `AI_API_BASE` / `AI_MODEL` | модель-судья (Groq) |

`ROGNAR_PHONE` нужен только при первом входе.

## Кого слушать

По умолчанию — **все групповые чаты аккаунта**. Личная переписка и
каналы-вещания не берутся никогда, а рабочие и семейные группы вписываются в
`ignore.txt`.

`watchlist.txt` добавляет чаты сверх этого — на случай, если автоподхват выключен.

## Инструменты разведки

```bash
python scout.py candidates.txt   # замерить чаты из списка
python find.py br es             # найти новые (ru, kz, ca, us, br, es)
python diag.py                   # проверить, живы ли текущие
```

`scout.py` читает историю публичного чата и считает **сообщений в час** —
вступать для этого не нужно. Это единственная честная метрика: счётчик «онлайн»
на превью-странице показывает, сколько человек держат приложение открытым, и
однажды выдал за перспективный чат, молчавший 218 дней.

> Все три работают с тем же файлом сессии, что и слушатель, поэтому на сервере
> его нужно остановить на время (`docker compose stop`).

## Настройка чувствительности

- `config.py` → `TRIGGERS` — зацепки по направлениям;
- `config.py` → `NOISE_RE` / `ASK_RE` — что считать объявлением и что это отменяет;
- `rognar.py` → `SCORE_FLOOR` (55) — ниже этой оценки сигнал не шлём;
- `rognar.py` → `DEDUP_WINDOW` — как долго не дёргать повторно одного автора.

Отказ модели **не** считается вердиктом «не лид»: сообщение уходит с пометкой
«не проверено AI». Пропущенный клиент дороже лишнего уведомления.

## Первый запуск на новой машине

```bash
pip install -r requirements.txt
python login.py     # Telegram пришлёт код, ввести вручную — один раз
python rognar.py
```

`start.ps1` — то же самое под Windows, с автоперезапуском после сбоя.

## Границы

- Аккаунт-слушатель видит все чаты, где состоит: под него отдельный номер, а не
  личный телефон сотрудника с рабочей перепиской.
- Telegram ограничивает число чатов на аккаунт (~500, с Premium ~1000).
- Массовые вступления — главный триггер антиспама, поэтому вступаем вручную и
  понемногу.
